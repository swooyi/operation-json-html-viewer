# LaTex 구분자 검사 오탐 사례: TeX 줄바꿈 뒤 괄호·대괄호

## 상태

- 기록일: 2026-07-14
- 결정: 코드 수정 보류
- 영향: 문항 내용과 MathJax 렌더링은 정상인데 뷰어의 LaTex 구분자 검사에서 경고가 발생할 수 있다.

## 재현 사례

190번과 191번은 모두 `cases` 안에서 TeX 줄바꿈 `\\`를 사용한다.

```tex
% 190번: 줄바꿈 뒤가 숫자
... &(x<-1)\\2x+3 &(x\ge -1)...

% 191번: 줄바꿈 뒤가 여는 괄호
... &(x<1)\\(x+1)+2 &(x\ge 1)...
```

190번은 경고가 없고 191번만 경고가 발생했다. 191번의 `$` 수는 16개로 짝이 맞으며, 수학적 계산과 정답 `②`, `\dfrac{31}{6}`도 정상이다.

## 원인

현재 검사 로직은 `\(`, `\)`, `\[`, `\]`를 단순 정규식으로 센다.

```js
unmatchedCount(value, /\\\(/g)
```

`\\(`는 실제로 TeX 줄바꿈 `\\` 뒤에 일반 괄호가 오는 표기다. 그러나 정규식은 두 번째 백슬래시부터 `\(`로도 인식하여, 존재하지 않는 수식 구분자 시작을 센다.

동일하게 `\\[`도 `\[` 수식 구분자로 오인될 수 있다.

`\{`, `\}`는 현재 검사 대상이 아니며 LaTex에서 중괄호 문자를 표시하는 명령이다. 향후 중괄호 검사 기능을 추가하는 경우에는 일반 문자로 제외해야 한다.

## 보류 중인 수정 방향

`\(`, `\)`, `\[`, `\]`의 앞에 연속한 백슬래시 개수를 세어 홀수일 때만 실제 수식 구분자로 처리한다.

| 표기 | 백슬래시 수 | 처리 |
|---|---:|---|
| `\(` | 1 | 수식 구분자로 검사 |
| `\\(` | 2 | TeX 줄바꿈 뒤 괄호로 보고 제외 |
| `\\\(` | 3 | 줄바꿈 뒤 수식 구분자로 검사 |

`$` 및 `$$` 검사는 이 사례의 원인이 아니므로, 수정 시 범위를 넓히지 않는다.

## 수정 시 회귀 확인

1. 190번: 경고 없음
2. 191번: 경고 없음
3. 실제 `\(x\)` 및 `\[x\]`가 한쪽만 있는 문자열: 해당 구분자 불일치 경고 유지
4. `\\[x]`처럼 TeX 줄바꿈 뒤 대괄호가 있는 문자열: `\[` 불일치 경고 없음
